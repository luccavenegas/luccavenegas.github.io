RFID Lobby Welcome System

AdventHealth, Corporate Strategy & FORGE · Strategy Intern · May–June 2026

A proof of concept for a Proto Luma, a life-size holographic display. Someone carrying an RFID badge walks up, a long-range reader picks up the badge, and the display switches from an idle loop to a personalized greeting, with nothing to tap. I built it end to end, from reader configuration through the software. The test ran on a laptop screen, and the software was designed so the same system can drive the Luma.

How it works

From a radio read to a video on screen

MQTT is the boundary between hardware and software. The reader publishes each badge read as a small JSON message with the tag ID and signal strength. Everything after that is software I wrote, so if the reader brand ever changes, only the listener has to change.

rfid_listener

Subscribes to the reader's topic, drops weak reads below the RSSI threshold, and de-bounces repeat reads into clean badge events.

logic_engine

Decides who to greet. When several badges show up at once it waits briefly and picks the strongest signal, then enforces the per-badge cooldown.

media_controller

Drives the mpv video player over its IPC interface, swapping from the idle loop to a greeting and back. Works on Windows, Mac or Linux.

health

Background checks: a heartbeat file, warnings when the reader goes quiet, offline alerts, and hot-reloading the badge list every 60 s.

Greeting the closest person

Signal strength (RSSI) is a rough stand-in for distance: the less negative it is, the closer the badge. If two people walk up together, the system greets whoever is physically closer instead of everyone at once, which also helps with privacy. Reads weaker than −70 dBm are ignored, which sets the trigger zone at about 5 ft.

What I delivered

A package someone else can run

  • Working software: four decoupled modules that talk through in-memory queues, so the display or the decision logic can be swapped without touching the rest.
  • Reader setup: antenna selection and power, MQTT endpoint configuration, and a way to capture each badge's ID.
  • Quickstart guide: blank laptop to working demo in about 60–90 minutes.
  • Troubleshooting guide: organized by symptom, from "nothing happens when I wave a badge" to "it feels laggy."
  • Handoff note: what's proven, what's still placeholder, and the path to a holographic display (Proto Luma) without rewriting the core logic.

The code and documents belong to AdventHealth, so they aren't published here.

What I learned

Lessons from the bench

  • Tune the radio before the code. Antenna power and the reader's session setting mattered as much as the code for how responsive it felt.
  • Pick a clean boundary. Putting MQTT between the reader and the software meant I could test each half on its own.
  • Plan for the real world. Auto-reconnect, outage alerts and a hot-reloading badge list are what let a demo run without someone babysitting it.
  • Be honest about scope. The handoff spells out what is proven on a laptop and what still needs real content and hardware.
